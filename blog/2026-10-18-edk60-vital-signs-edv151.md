在睡眠监护、康养看护这类场景里，**非接触式测量呼吸与心率**一直是刚需——不能要求被测者佩戴任何东西，还要能长期稳定工作。

我们用 **EDK60 开发板**（ESP32-C6）搭载 **EDV151 生命体征雷达模组**，做了一套完整的参考方案：雷达测得的呼吸率与心率，通过 ESP32-C6 的**原生 USB** 直接送到电脑，**不需要 USB 转串口芯片、PC 端也不需要安装任何驱动**。

实测环境下，静坐受测者可稳定输出 **心率 75 bpm、呼吸率 21 bpm**，数据每秒上报一次，串口校验零错误。

## 场景需求

| 需求 | 说明 |
|---|---|
| 非接触 | 被测者不佩戴、不接触任何设备 |
| 测呼吸与心率 | 不只是"有人/无人"，要给出具体数值 |
| 实时上报 | 秒级刷新，便于上位机做趋势与告警 |
| 易于集成 | 提供可复现的硬件与固件，客户能自行二次开发 |

典型场景：卧室睡眠监测、养老院床位看护、婴儿房监护、独立办公位的疲劳与压力趋势分析。

## 方案构成

```text
EDV151 雷达模组
   │  串口 921600 8N1
   ▼
EDK60（ESP32-C6）
   │  原生 USB（免驱动）
   ▼
PC 上位机
```

| 环节 | 器件 / 技术 | 关键点 |
|---|---|---|
| 感知 | EDV151 生命体征雷达 | 输出睡眠状态、体动、心率、呼吸率及其可信度 |
| 主控 | ESP32-C6（EDK60 开发板） | UART 与模组通信，USB 与 PC 通信 |
| 连接 | **芯片原生 USB** | 省掉 USB 转串口芯片，免驱动、免外部晶振、免电平转换 |
| 上位机 | 任意串口工具 / 自带工具 | USB CDC，波特率不敏感 |

## 接线与引脚

实测确认的引脚（与早期读图结论不同，以下为最终版）：

| 信号 | 引脚 | 说明 |
|---|---|---|
| 模组 TX → MCU RX | **IO4** | UART 接收 |
| 模组 RX ← MCU TX | **IO5** | UART 发送（下发配置命令） |
| 雷达电源使能 EN | **IO14** | 输出高 = 3.3V_RADAR 上电 |
| 橙色指示灯（丝印 L） | IO15 | 仅指示，不参与电源控制 |
| 串口参数 | 921600 / 8N1 | — |

:::warning 模组插在 H3，不是 H4
板上 H3 与 H4 两个 8 pin 排针信号集合相同但**顺序相反**：
H4 的 `T` 脚与电源使能是同一网络，插 H4 会导致电源与数据互相干扰。
**请插 H3。**
:::

## 实现要点

### 1. 模组射频默认关闭，必须由主控开启

EDV151 上电后只会主动发两类握手帧：`radar_ready`（就绪）与 `get_time`（请求校时）。
**不开射频就不会有任何体征数据**。固件在启动时自动完成 6 条握手命令：

| # | 命令 | 作用 |
|---|---|---|
| 1 | `turn_on` | **打开射频**（不发则完全没有体征数据） |
| 2 | `set_time <epoch>` | 校时 |
| 3 | `set_para 4:1` | 上报周期 1 秒 |
| 4 | `set_para 5:30,6:150` | 检测范围 30~150 cm |
| 5 | **`set_gain 0.5`** | **降低灵敏度（关键，见下节）** |
| 6 | **`set_boost 2`** | 中心区域增强 |

### 2. 串口协议

帧结构为 `0x5A` + 长度 + 消息 ID + ASCII 载荷 + 异或校验：

```text
+------+--------+--------+---------------+--------+
| 0x5A |  LEN   |   ID   |    PAYLOAD    |  XOR   |
+------+--------+--------+---------------+--------+
```

消息 ID `0x00~0x7F` 为雷达上报，`0x80~0xFF` 为主控请求（应答沿用请求 ID）。

体征数据帧：

```text
vital_signs <睡眠状态>,<距离cm>,<体动>,<心率bpm>,<呼吸率bpm>,
            <心率状态>,<呼吸状态>,<心率可信度>,<呼吸可信度>
```

其中 `心率` / `呼吸率` 为 `0` 表示尚未识别；可信度 0~4，越高越可信。

## 关键发现：增益过大会让心率呼吸"永远是 0"

这是整个调试过程中最难定位的一个问题，值得单独说明。

### 现象

- 雷达**能稳定检测到人**：距离一直有值（40~60 cm）
- 但 `心率 = 0`、`呼吸率 = 0`，**一直不出数**
- 关键线索：`体动` 一直在 **20~60** 之间，可人明明是坐着不动的

### 根因

体征算法要求**静息体动 < 5** 才肯计算。出厂参数 `gain=4 / boost=0` 灵敏度过高，
把呼吸、心跳之外的微小扰动都算成了"体动"，算法于是认为目标在动，永远不计算体征。

### 解决与效果

把增益与增强模式改成官方推荐的 `set_gain 0.5` + `set_boost 2` 后：

| 参数 | 体动 | 心率 | 呼吸率 |
|---|---|---|---|
| 出厂 `gain=4 / boost=0` | 20~60 | **0（永不识别）** | **0（永不识别）** |
| 调整后 `gain=0.5 / boost=2` | **1~6** | **75 bpm** | **21 bpm** |

> 这条经验已固化进固件：设备开机自动下发，用户无需手动调参。

## 实测结果

| 指标 | 实测值 | 测量条件 |
|---|---|---|
| 心率 | 75~84 bpm | 成年男性静坐，距雷达 43~58 cm，室温，静息 |
| 呼吸率 | 18~21 bpm | 同上 |
| 检测距离 | 43~58 cm | 协议字段分辨率 1 cm，未做标准距离标定 |
| 体动幅度 | 1~6（静息） | 越大越难算体征 |
| 帧率 | 1 帧/秒 | `set_para 4:1` |
| 校验错误 | 0 / 255 帧 | 921600 8N1，连续采集 3 分钟 |
| 首次出数时间 | 约 20~40 秒 | 人坐稳后开始计 |

睡眠状态字段还会给出 `清醒 / REM / 浅睡 / 深睡 / 翻身` 的判定；
模组在睡眠结束后另有一条 `sleep_quality` 帧，包含睡眠评分、效率与各阶段占比，
可直接用于生成睡眠日报。
