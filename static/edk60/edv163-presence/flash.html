EDK60_VA V1.0（ESP32-C6）+ EDV163-N-03 人体存在检测雷达的纯字节双向透传桥固件。 不需要安装任何软件。用 Chrome 或 Edge 浏览器打开本页，插上 USB 线，点按钮即可。 协议口径按《EDV163-N-03 串口通信协议 V1.4》（2026-11-04）。

先说清楚这三个字：「透传桥」。
本页烧的是 EDV163 纯字节双向透传桥固件——它与站内水位示例 （level.html）是同一个固件，SHA256 相同， 只是换了文件名 edk60_edv163_bridge.bin 以便人存演示页对照引用。
桥固件本身一行协议代码都没有：0x81 上报解析、有人/无人判定、X-Y 轨迹与检测范围绘制、 屏蔽区、静默推断，全部在网页端（presence.html）完成。想改判定逻辑、加新图表， 只改网页即可，不需要重新烧板子。
波特率对齐：V1.4 协议仍然固定 256000 8N1 无流控，与本透传桥固件一致 —— 所以这次协议升级不需要重新烧固件，只换网页即可（帧格式的变化全在网页端解析）。

烧完之后

  1. 拔掉 USB 线，等 2 秒，再插回去（让板子重新启动）
  2. 看板子上的 丝印 RADAR 的红灯：亮了 = 雷达已上电，正常
  3. 打开演示页 presence.html（同一目录，也可以直接点这个链接）
  4. 在演示页里点 「连接串口」，在弹窗里选那个 USB 串行设备； 串口参数固定 256000 8N1 无流控，页面已设好，不要改成 921600
  5. 连上后演示页会自动发 13 条只读 GET（0x01 0x02 0x12 0x17 0x18 0x1B 0x1D 0x23 0x24 0x25 0x26 0x27 0x29），右栏「参数回读」逐条填上设备真实值 （未应答的显示「超时未回答」，不猜值）
  6. 想让演示「走得快」：到右栏点一次 「应用演示推荐参数…（需确认）」并在总确认框里点确定， 会逐条下发 5 条 SET：0x17=10（上报周期 1 s）、0x12=1（闭锁 1 s）、 0x24=0（正常运动触发）、0x25=2500（挂高 2500 mm）、 0x18=1（射频正常），每条都等 0xA2 应答并回读比对
演示页是「默认只读」的：连上之后只发 13 条查询指令（op=0xA0）， 不改写模组配置；任何写入都必须你先点按钮并在确认框里点确定， 且逐条发送、逐条等应答、逐条回读比对（单条 500 ms 超时即中止）。
高危命令 0x1F / 0x1A / 0x20 / 0x21 / 0x22 默认禁用，需先勾「我已知晓」解锁， 再连过两道确认（含手动输入该命令的 type 十六进制）才会发出。
如果没有硬件，演示页里的「运行页内自测」（16 条用例）与「注入 0x81 样例 / 注入范围/屏蔽区样例」 都不依赖串口，可以先确认整条渲染管线。

这套固件做什么

它是一根双向透明的桥：EDK60 板上的 ESP32-C6 把 EDV163-N-03 雷达串口上的字节 原样转发到板子的原生 USB（CDC，免驱），固件本身不做任何协议解析。 雷达上报的每一帧都完整送到上位机；有人/怎么判定、坐标怎么画、轨迹与检测范围怎么渲染， 全部在网页端完成——雷达固件升级、协议字段调整都不需要重新烧板子。

帧格式帧头 45 44 ｜ 长度 = 11 + N ｜ msgid(2) ｜ op(1) ｜ type(1) ｜ len(2) = N ｜ Value(N) ｜ 校验和(1)。没有帧尾 0x0A； 不做字节填充（Value 里的 0x09 / 0x0A 保持原值）； 校验和 = 自 45 起至 Value 末逐字节累加 mod 256（等价于 sum(data[0:-1]) 的末字节）
切帧规则只靠帧头 + 长度字段：半包保留等待；长度不在 11~256（256 是实现护栏、非协议条款） 判非法并只丢 1 字节再找帧头；帧头前的无归属字节计数后丢弃。 注意官方 0x01 的 Report 帧 Value 里就含 45 44，所以绝不能靠「再找一个帧头」切帧
上报帧op=0xA3 / type=0x81：固定 9 B 单目标 （有人 1B / 状态 1B / 方向 1B / X int16 大端有符号 / Y int16 大端有符号 / Z uint16 大端无符号，mm）。V1.4 已删除 0x13 检测通道数量， 没有「通道」概念：长度 ≠ 9 一律判「载荷长度异常」并把原始十六进制打出来
上板实测❌ 尚未在 EDV163-N-03 实物上验证（模组当前烧的是其它固件，换固件后才能测）
已有验证网页端解析器自测 16/16 + 额外回归 63 项（node scripts/edv163_presence_selftest.mjs， 抽的是 presence.html 里同一份解析器代码；断言数以脚本实跑输出为准）；
V1.4 §4 全部 39 条示例帧（19 组主机+应答，另 1 条 0x81 主动上报）回归： 39 条帧的长度域、校验和逐字节对齐，且全部可由代码重新生成。 以上均为无硬件验证，不能替代实机数据

常见问题

1. 烧好了，但我用串口助手打开只看到一堆乱码 / 乱字符？
这是正常的，不是坏了。本固件转发的是雷达的二进制协议帧（以 0x45 0x44 开头， 中间含不可打印的二进制字节），不是文本。串口助手默认按文本显示，自然就是乱码。
→ 想看有意义的内容，请用演示页 presence.html（它按 V1.4 解析并画状态卡 + 俯视轨迹）
→ 想在串口助手里看，切到 Hex / 十六进制显示，端口参数必须是 256000 8N1；参数填错时连十六进制也是错乱的
2. 模组插在 H4 上行不行？
不行。H3 与 H4 的信号集合相同但顺序相反：H4 上模组的 T（数据）与 电源使能落在同一网络，插 H4 会造成电源与数据互相干扰——典型现象是红灯忽明忽暗、 串口要么没数据要么全坏帧。
→ 断电后把模组移到 H3，插紧，再上电
3. 网页连不上串口 / 点了没反应 / 根本没有按钮？
→ 浏览器不对：只有电脑版 Chrome / Edge 89+ 支持 Web Serial；Firefox、Safari、 手机浏览器、微信内置浏览器都不支持
→ 页面不是安全上下文：Web Serial 与烧录都只在 https 或 localhost 下可用。用本站 https 页面访问即正常；直接双击打开本地 file:// 文件会失败， 本地测试请在该目录起一个静态服务（例如 py -3 -m http.server 8771）再访问 localhost:8771/presence.html
→ 串口被占用：关掉串口助手、Arduino IDE、其它浏览器标签页后重试
→ 还不行：换一根能传数据的 USB 线（很多充电线只有电、没有数据），优先插机箱后面的 USB 口
4. 波特率为什么要 256000？能不能用 921600？
不能。EDV163 这一代雷达的串口固定 256000 8N1 无流控（V1.4 与 V1.1 都一样）， 和 EDV151 / EDV11P 用的 921600 不是一个档位。波特率填错的表现是： 串口能打开、但一个合法帧都收不到，统计条坏帧数与总字节数会一直往上飙。
→ 演示页已把 256000 写死在代码里且不提供改档；自己写程序对接时务必对齐这一档。
→ 另注：EDK60 是 ESP32-C6 原生 USB CDC，浏览器里的波特率不影响板载 UART 线速， 但为了不误导，两处都钉死 256000
5. 页面显示「无人（按静默推断）」，是不是设备挂了？
不是。协议的口径是「触发有人后每隔 0x17 周期上报一次 0x81」， 所以无人期间可能完全静默。演示页因此把「无人（按静默推断）」与「链路故障」 做成了两个独立状态：
→ 超过 max(3 × 上报周期, 8 s) 没收到 0x81 → 大字显示「无人」， 并标注按静默推断（这不是故障）。它有两种原因： ① 真的无人；② 有人但完全静止、没被运动触发 —— 所以若刚有运动触发过，请勿据此判无人
→ 只有「一个合法帧都收不到」「坏帧率 > 20%」这类情况才判链路故障， 在状态卡上用红色「链路 …」标签单独显示
→ 想确认雷达还在工作：把 0x17 设成 10（1 s），然后站到雷达前面走两步， 看事件时间线是否有「无人 → 有人」
6. 页面一直「等待数据」，一个 0x81 都没有？先看两个开关。
→ 射频是不是被关了：读一下 0x18，若回读为 0（关闭雷达射频） 设备不会产生任何上报，演示页顶部会显式告警「射频已关闭」。下发 0x18 = 1 恢复
→ 触发使能 / 上报周期：0x1B（触发使能）应为 1；0x17 默认 50 （= 5 s），演示时建议先下发 0x17 = 10（1 s），否则看起来像卡住
→ 两个都不是：看统计条的 坏帧 / 未归属 / 校验和错 / 帧头重同步 四个计数。 坏帧不为 0 通常是波特率档位不对或线材问题；总字节一直是 0 则是串口没通
